# PR-06.3: compact JSON + env-var caps + maxResultSizeChars annotation — план

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development.

**Goal:** Закрыть 3 связанных issue, выявленных при ручном тестировании PR-06.2:

1. **Cap mismatch bug:** view_toc меряет лимит на compact-сериализации (`JSON.stringify(response)`), а отдаёт pretty-print (`JSON.stringify(response, null, 2)`). Реальный output ~28.5 KB при cap 25 KB без сигнала `truncated`. Решение — compact JSON везде.
2. **Hardcoded caps без конфигурации:** `MAX_VIEW_TOC_BYTES = 25 * 1024` и `MAX_SECTION_BYTES ≈ 200 * 1024` — хардкод. Решение — env vars `MARKDOWN_DOCS_MAX_TOC_BYTES`, `MARKDOWN_DOCS_MAX_SECTION_BYTES` + поднять дефолт view_toc cap до 50 KB.
3. **No Claude Code annotation для larger inline:** Claude Code v2.1.91+ поддерживает `_meta["anthropic/maxResultSizeChars"]` annotation (до 500K chars), позволяющую MCP-серверу запросить больший inline-буфер. Решение — добавить annotation на все 4 tools.

**Architecture:**
- NEW: `src/config.ts` — env-var parsing, validation, default fallback.
- `createServer({ cache, config })` — config injected via DI, передаётся в response builders.
- `_meta: { "anthropic/maxResultSizeChars": 200_000 }` annotation на view_toc и read_section.
- Compact JSON во всех 4 handler'ах (без indent).

**Tech Stack:** уже подключено. SDK 1.29 поддерживает `_meta` в `registerTool` config (verified в `mcp.d.ts:156`).

**Связь с PR-06.2:** прямое продолжение, hotfix контракта cap'а.

**Ветка:** `pr-06.3-cap-fix-and-env` от `dev`.

## Контракт

### `src/config.ts`

```ts
export type Config = {
  maxViewTocBytes: number;
  maxSectionBytes: number;
};

export const DEFAULT_CONFIG: Config = {
  maxViewTocBytes: 50 * 1024,   // 50 KB (было 25 KB; compact-JSON даёт +40% запас)
  maxSectionBytes: 200 * 1024,  // 200 KB (не менялось)
};

export function loadConfig(env: NodeJS.ProcessEnv = process.env): Config {
  return {
    maxViewTocBytes: parsePositiveInt(env.MARKDOWN_DOCS_MAX_TOC_BYTES, DEFAULT_CONFIG.maxViewTocBytes, "MARKDOWN_DOCS_MAX_TOC_BYTES"),
    maxSectionBytes: parsePositiveInt(env.MARKDOWN_DOCS_MAX_SECTION_BYTES, DEFAULT_CONFIG.maxSectionBytes, "MARKDOWN_DOCS_MAX_SECTION_BYTES"),
  };
}
```

- Invalid value (non-numeric / ≤ 0): write `console.warn(...)` к stderr, fallback to default. **Не падать** при старте сервера.
- `MAX_VIEW_TOC_BYTES` upper bound: 500_000 (annotation cap); если задан больше — clamp + warn.

### `createServer`

```ts
export type ServerDeps = { cache?: IndexCache; config?: Config };

export function createServer(deps: ServerDeps = {}): McpServer {
  const cache = deps.cache ?? new IndexCache();
  const config = deps.config ?? DEFAULT_CONFIG;
  // handlers получают config
  ...
}
```

### Annotation в `server.registerTool`

```ts
server.registerTool("view_toc", {
  description: VIEW_TOC_DESCRIPTION,
  inputSchema: viewTocInput,
  _meta: { "anthropic/maxResultSizeChars": 200_000 },
}, async (args) => viewTocHandler(args));
```

То же на `read_section`. Search и analyze_document — без annotation (их ответы меньше, fits под дефолтный token cap).

### Compact JSON

Во всех 4 handler'ах:
```ts
return { content: [{ type: "text", text: JSON.stringify(response) }] };
```
Удаляем `, null, 2`.

## Acceptance criteria

После merge PR-06.3:

1. `pnpm typecheck && pnpm test && pnpm build` зелёные.
2. `view_toc` real output bytes (`Buffer.byteLength(content[0].text)`) ≤ `MARKDOWN_DOCS_MAX_TOC_BYTES` ALWAYS (нет ложно-отсутствующего `truncated`).
3. Compact JSON: output не содержит `, null, 2` artifacts (нет лишних пробелов).
4. `tools/list` показывает `_meta["anthropic/maxResultSizeChars"]: 200_000` на view_toc и read_section.
5. `MARKDOWN_DOCS_MAX_TOC_BYTES=10240` env override работает: TRM view_toc возвращает `truncated=true` уже при depth=2 или меньше.
6. Invalid env-var values — warn + fallback to default, сервер стартует.
7. TRM stress тест продолжает проходить с новым дефолтом 50 KB.

## Anti-patterns

- Не делать annotation на search/analyze_document (их ответы маленькие, не нуждаются).
- Не превращать `Config` в singleton — DI через `createServer` параметр.
- Не парсить env vars в response builders — config грузится один раз в `index.ts`.
- Не падать при невалидном env var — warn и fallback.
